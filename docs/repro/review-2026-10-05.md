## Floating-point draft review

The field count 2+1+5+19=27 is consistent. Five balanced exponent trits span -121..121.
However, the value formula and normalization are incomplete. Before implementation:

1. Define an exact rational value for every finite encoding, the radix point,
   exponent scaling and implicit leading digit.
2. Resolve sign=0 as a subnormal marker: the draft also calls the significand an
   unsigned magnitude, leaving negative subnormal values without a stated sign.
3. Define signed/unsigned zero, infinity sign validity, NaN payloads and reserved
   encodings. `tfloat27{}` currently gives the first enum (infinity) with sign=0,
   rather than a clearly defined zero value.
4. Specify enum-to-two-trit mapping and digit/byte order. Pack/unpack round trips
   alone do not prove a stable wire format; use fixed external vectors too.
5. Separate numeric comparison from total ordering. Returning 0 for an unordered
   NaN would collide with equality; the declaration has no returned unordered flag.
6. Validate raw int8_t fields and distinguish zero from subnormal classification.
7. Exhaustively classify all 729 Ternary6 encodings before scaling up. Reserved or
   invalid states need explicit outcomes, not an assumed valid numeric value.

This draft remains an RFC, not a stable core API. The public files are preserved in
Git; the candidate does not silently promote them to implemented floating arithmetic.

## Architectural conclusions

Balanced ternary and a 27-trit word remain coherent research choices, but the width
is a project choice, not proof of an optimal CPU. 27 trits encode about 42.8 bits of
information. The present C++ word occupies 27 bytes on the tested host; a 2-bit-per-trit
FPGA representation would occupy 54 bits. These are different representation layers.

A ternary ISA emulated on binary hardware can be a useful next milestone. It does
not by itself demonstrate a hardware energy/area advantage. Such claims need a
specified technology, matched binary baseline, workload, I/O/memory costs and measurements.

Stochastic computing needs its own number representation and statistical contract.
In particular, E[XY]=E[X]E[Y] depends on zero covariance (independence suffices).
Correlated generators must be tested; a lane-rate estimate is not an accuracy or
energy-efficiency result. Keep this research track separate from deterministic CPU
instruction semantics until a coprocessor interface is specified.

An OS should follow an executable ISA model, boot path, ABI, I/O and interrupts.
The library alone does not define a processor or its memory model. Nothing in this
review establishes patent clearance, historical novelty, or measured silicon results.
